# DungeonQ product direction

## Canonical definition

DungeonQ is a defensive deception runtime. At a designated entry point, a trusted gateway routes an explicitly admitted suspicious human or AI session into a separate persistent synthetic world. The participant can continue useful work there, including using a Wrong Ticket whose authority exists only inside its issuing world. Operators retain observations and may authorize finite adaptation. Independent evidence checks where the participant's authority stopped and whether the named artificial origin remained untouched.

The current self-hosted reference and its acceptance evidence are maintained in [`Ranopha/dungeonq-astra`](https://github.com/Ranopha/dungeonq-astra).

## Role of this repository

This repository preserves the concluded OpenAI WebMCP Challenge entry. It is a **Competition Profile** around a browser-local **Proof Kernel**. It demonstrates:

- closed and bounded synthetic Scenario Pack admission;
- deterministic decision and proposal digests;
- state-shaped WebMCP tools;
- absence of an agent approval tool;
- exact revision and idempotency claims;
- receipt and evidence tamper detection; and
- append-only compensation.

These properties are useful inside the wider DungeonQ system. They are not the host adapter, diversion decision, persistent synthetic world, Wrong Ticket issuer, participant observation pipeline, adaptive mutation runtime or artificial-origin witness.

## Claim boundary

| Capability | This WebMCP profile | Current DungeonQ reference |
|---|---|---|
| Browser and CLI Proof Kernel | Implemented and reproducible | Retained as a supporting capability |
| WebMCP state-shaped tools | Implemented | Optional client/profile surface |
| Trusted host entry | Not implemented | Explicitly provisioned reference adapters |
| `DIVERT` to a separate world | Simulated label only; not counted as diversion | Server-side routed reference journey |
| Persistent world across restart | Not implemented | Implemented for artificial resources |
| Useful Wrong Ticket | Not implemented | Bounded world-only authority |
| Participant observation | Not implemented | Retained synthetic activity history |
| Adaptive mutation | Not implemented | Finite operator-approved follow-up records |
| Production protection | Not claimed | Not claimed; requires environment-specific acceptance |

## Contribution rule

Future work in this repository must keep the distinction visible. A WebMCP action may inspect or operate an authorized DungeonQ surface, but WebMCP annotations, browser state, UI labels and imported Scenario Packs cannot be presented as routing authority or proof of diversion. Historical submission documents remain preserved and dated; the README and live page carry the canonical product relationship.
